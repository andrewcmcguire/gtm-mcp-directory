# The GTM MCP Directory

**293 go-to-market tools, scored on the one axis nobody else publishes: can an
AI agent actually call this, and can a solo operator get in without a
procurement cycle.**

Browse it: **https://gtm-mcp-directory.pages.dev**
(its home is andrewcmcguire.com/gtm-directory once that route is live)
Query it from your agent: the MCP server in [`server/`](server/).
The whole dataset, no key, no signup: [`data/directory.json`](data/directory.json).

Every GTM tool list on the internet ranks tools for humans to buy. This one
answers a different question. Your agent is going to try to call these tools.
Which ones can it reach, which ones have an official server behind them, and
which ones will bounce you into a sales cycle before you get a key.

## Install the MCP server

Seven tools, answering "which tools do X and can I actually reach them" from
inside your agent. It loads a baked JSON file at startup and answers from
memory: **zero outbound requests**, at startup or at query time. It cannot be
slow, cannot cost anything, cannot rate-limit you, and cannot leak your query
to a vendor.

The package is **not on PyPI yet**, so run it from a clone:

```bash
git clone https://github.com/andrewcmcguire/gtm-mcp-directory
cd gtm-mcp-directory/server
python -m gtm_mcp_directory        # stdio, blocks, speaks MCP
```

Point a client at it:

```json
{
  "mcpServers": {
    "gtm-directory": {
      "command": "python",
      "args": ["-m", "gtm_mcp_directory"],
      "cwd": "/absolute/path/to/gtm-mcp-directory/server"
    }
  }
}
```

Requires Python 3.12+. Full tool reference, every filter, every environment
variable and the integrity model: **[`server/README.md`](server/README.md)**.

## Browse the site

**https://gtm-mcp-directory.pages.dev**

461 static pages, no framework, no tracking, and zero external requests at
runtime (enforced by a CSP, not just claimed). One page per tool with every
field verbatim and its sources, plus category, MCP-status, access-gate, job

Built for machines as much as people: every page has a **markdown twin** at the

## The honesty tiers

The tier is the product. It is on every response the server gives and every
page the site renders, and it is never optional.

| Tier | What it means |
|---|---|
| `RESEARCHED` | Facts from public sources, with URLs. No usage claims. **Nobody has run this tool.** |
| `BENCH-TESTED` | Andrew personally ran it, on a stated date. **Cannot be bought.** |

**All 293 entries are RESEARCHED. Zero are BENCH-TESTED.** That number stays at
zero until somebody actually runs something and says so with a date.

Three more rules the data keeps:

- **A job tag means the vendor says the tool does this.** It is not a test
  result, not a benchmark, not an endorsement. 271 entries carry tags and all
  271 were tagged by a machine pass over the entry's own description text, not
  read by a human. Every entry publishes `jobs_tagged_by` and `jobs_tagged_on`
  so you can tell which pass produced a tag.
- **Unmeasured is not the same as zero.** `github_*` and `docs_digest` are null
  everywhere because nothing has been measured for them yet, and the data says
  which is which instead of letting a null read as a finding.
- **No tool-versus-tool verdicts anywhere.** With `bench_tested` at 0, a
  comparison would be an opinion wearing a number's clothes.

The build enforces the counts, too: it **fails and writes nothing** if its
totals disagree with the counting authority on any file, any bucket, any name
sequence, the grand total, or the duplicate set. A drifted count never ships.

## Submit a tool

Free, and a submission is not a listing.

**[Open the submission form](https://github.com/andrewcmcguire/gtm-mcp-directory/issues/new?template=tool-submission.yml)**

Every claim gets checked by hand against the vendor's own documentation before
anything lands in the data. If an MCP server is claimed, the URL has to resolve
to something real. Corrections to an existing entry are welcome through the same
form, and the fastest way to get a correction accepted is a link to the vendor
page that contradicts what is published here.

Contact name, role and email are collected and never published.

## What is in this repo

```
data/
  directory.json     the baked artifact, 293 entries, every field verbatim
  build_report.json  machine-readable build + reconciliation report
  BUILD_REPORT.md    the same report, for a human
  jobs.yaml          the closed capability vocabulary, 55 jobs in 10 families
  tags.yaml          which entry carries which job tag, and who tagged it
src/
  build_directory.py the builder: hand-edited markdown -> directory.json
server/              the MCP server (see its own README)
site/
  generate_site.py   the site generator
  ...                the generated site, committed, so the repo is the artifact
```

Stdlib only, Python 3.12, no install step, no dependency, no network call in
either the builder or the server.

```bash
python src/build_directory.py --check      # validate, write nothing
python src/build_directory.py              # rebuild the data
cd site && python generate_site.py --check # rebuild the site, validate output
```

`--check` on the site generator is a stop, not a warning: it fails on a broken
link, an external asset, an executable inline script, an unparseable JSON-LD
block, a markdown twin that drifted from its page, or an em dash.
